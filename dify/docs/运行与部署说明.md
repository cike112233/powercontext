# 运行与部署说明（从零复现）

目标：在一台装了 Docker + Node 的机器上，把「seekdb 面试陪练官」完整跑起来，并能自己重跑全部调用证据。全程只用本地服务与占位凭据，DeepSeek Key 由你自己填。

预计耗时：镜像拉取 10-40 分钟（取决于网络），其余步骤 15 分钟左右。

## 0. 前置条件

| 依赖 | 要求 | 备注 |
| ---- | ---- | ---- |
| Docker | Desktop ≥ 4.x / Engine ≥ 24，可用内存 ≥ 8GB | seekdb 限 2G，Dify 全家桶约 4G |
| Node.js | ≥ 20（本项目用 v24） | 脚本为零依赖 ESM，只有两个服务需要 `npm install` |
| Dify 源码 | `git clone -b 1.18.0 https://github.com/langgenius/dify.git` | 只需要其中的 `docker/` 目录 |
| DeepSeek 账号 | 一个可用 API Key | 只在你本机生效，绝不提交 |
| 本仓库 | `dify/` 目录 | 语料、DSL、脚本、服务都在这里 |

国内网络提示（实测）：Docker Hub 直连不稳定，需自备镜像加速；`marketplace.dify.ai` 在容器内直接失败，所以插件走离线 `.difypkg` 安装；HuggingFace 换 `hf-mirror.com`（`dify/embedding/scripts/fetch-model.mjs` 已按此实现）。

## 1. 配置 Dify 使用 seekdb 作为向量库

```bash
cd dify/docker            # Dify 源码里的 docker 目录
cp .env.example .env
```

编辑 `.env`，只需改这三处（其余保持默认）：

```ini
# 1) 选中 seekdb 向量库。COMPOSE_PROFILES 已经写成 ${VECTOR_STORE} 派生，
#    设了这一行，compose 会自动带起 seekdb 容器，无需额外 profile 参数。
VECTOR_STORE=seekdb

# 2) 让容器能访问宿主机上的自研检索服务（见第 5 节）。
#    Docker Desktop（Win/Mac）里 host.docker.internal 解析为 192.168.65.254；
#    Linux 上如果配置了 host-gateway，一般取 docker0 网段地址，如 172.17.0.1。
SSRF_PROXY_ALLOW_PRIVATE_IPS=192.168.65.254

# 3) 离线安装插件时跳过签名校验（Dify 默认要求插件带 marketplace 签名）。
FORCE_VERIFYING_SIGNATURE=false
```

`docker/envs/vectorstores/seekdb.env` 保持默认即可（它就是官方占位值）：

```ini
OCEANBASE_VECTOR_HOST=seekdb
OCEANBASE_VECTOR_PORT=2881
OCEANBASE_VECTOR_USER=root
OCEANBASE_VECTOR_PASSWORD=difyai123456     # 本地占位口令，请自行修改
OCEANBASE_VECTOR_DATABASE=test
OCEANBASE_ENABLE_HYBRID_SEARCH=true         # 关闭时 Dify 不会建全文索引，也就没有混合检索
OCEANBASE_FULLTEXT_PARSER=ik                # 中文必须指定 ik
SEEKDB_MEMORY_LIMIT=2G
```

启动：

```bash
docker compose up -d
docker ps --format '{{.Names}}\t{{.Status}}' | grep seekdb     # 期待 (healthy)
```

`docker-compose.yaml` 里 seekdb 服务把 2881 映射到宿主机，宿主机上的自研检索服务因此可以直接连它。

## 2. 初始化管理员账号

首次启动后必须做一次 setup，否则所有 console API 都会 401。用本仓库脚本（凭据为本地占位值）：

```bash
bash dify/deploy/init-setup.sh
# 等价于 POST http://localhost/console/api/setup
#   {"language":"zh-Hans","email":"admin@seekdb.local","password":"Seekdb2026Demo","name":"seekdb-demo"}
```

打开 http://localhost 用该账号登录。**这一步之后所有脚本都复用同一对凭据**：

```bash
export DIFY_ADMIN_EMAIL=admin@seekdb.local
export DIFY_ADMIN_PASSWORD=Seekdb2026Demo
```

## 3. 起两个本地服务（embedding + seekdb 混合检索）

一条命令搞定（会自检容器、按需 `npm install`、按需下载模型、后台拉起并把 pid 和日志写到 `dify/tmp/`）：

```bash
bash dify/deploy/start-all.sh
# 关闭：bash dify/deploy/start-all.sh stop
```

验证：

```bash
curl -s http://127.0.0.1:8100/health     # embedding：{"status":"ok","model":"Xenova/bge-small-zh-v1.5","dtype":"q8","dim":512}
curl -s http://127.0.0.1:3012/health     # 检索工具：{"status":"ok","seekdb":{...},"table":"vector_index_<dataset>_node","segments":162}
```

说明：embedding 用的是 Task3 端侧同款的 `bge-small-zh-v1.5`（512 维、q8 ONNX、运行期零外网）。检索工具服务连的 seekdb 参数走环境变量，默认 `127.0.0.1:2881 / root / difyai123456 / test`；表名要等知识库建好才知道，所以**第 4 节先建库、第 5 节再回头配表名**（也可以先跑第 4 节再回到这里）。

## 4. 配置模型 → 建知识库 → 导入语料

```bash
cd dify/scripts
node setup-models.mjs
#  - 注册本地 embedding（OpenAI-API-compatible，endpoint 填 http://host.docker.internal:8100/v1，key 为占位串）
#  - 把它设为系统默认 text-embedding，知识库才会用它做向量化
#  - 未提供 DEEPSEEK_API_KEY 时跳过 LLM：请在 Dify 后台「集成 → 模型供应商 → DeepSeek」填一次 Key
#    （DSL 里用的是 deepseek-flash；若想换模型，在 LLM 节点重选或导出后改 dsl/interview-coach.yml）

node import-kb.mjs
#  - 建/复用知识库「面试陪练知识库」，按 "###" 自定义分块导入 dify/kb/*.md（11 文件 / 162 题 → 162 个检索块）
#  - 轮询 indexing-status 直到每个文档 completed，并打印 dataset_id
#  - 幂等：同名文档跳过；改了语料想重建索引就加 --reindex

export DIFY_DATASET_ID=<上面打印的 dataset_id>
node set-dataset-hybrid.mjs
#  - PATCH 知识库 retrieval_model.search_method = hybrid_search
#    这是 Dify 原生检索走「全文+向量」的前提；不改也不用重建库，直接生效
```

到这里，通路 A 已经完整：Dify 把向量与全文都写进了真实 seekdb。验证（把 `<dataset_id>` 换成你的）：

```bash
docker exec seekdb sh -c "mysql -h127.0.0.1 -P2881 -uroot -pdifyai123456 -Dtest -e 'SHOW TABLES; SHOW INDEX FROM vector_index_<dataset_id>_node'"
# 期待看到 Index_type 同时含 VECTOR 与 FULLTEXT；对照 evidence/seekdb-native-proof.txt
```

## 5. 注册自研 seekdb 混合检索自定义工具

先确认 `dify/retrieval/openapi.yaml` 里的 `servers.url` 指向你本机的检索服务：

```yaml
servers:
  - url: http://192.168.65.254:3012      # Docker Desktop 里 host.docker.internal 的地址
```

然后：

```bash
node setup-custom-tool.mjs --test
#  - 走 console API 建/替换名为 seekdb_hybrid_search 的自定义工具供应商（auth_type: none）
#  - --test 会真实调一次 /tool-provider/api/test/pre，打印命中结果与 EXPLAIN
```

如果 `--test` 报 `ERR_ACCESS_DENIED` 或连不上，九成是第 1 节的 `SSRF_PROXY_ALLOW_PRIVATE_IPS` 没生效：改完 `.env` 必须重建代理容器 `docker compose up -d ssrf_proxy`。

## 6. 导入并发布应用

```bash
node import-dsl.mjs ../dsl/interview-coach.yml --publish --export ../dsl/interview-coach.exported.yml
#  - 导入前自动把 DSL 里的 dataset_ids 换成 DIFY_DATASET_ID、provider_id 换成你工作区的真实工具 UUID
#  - --publish 用草稿发布；--export 把服务器规范 DSL 落回仓库，作为「线上就是这个版本」的对照
#  - 输出里的 app_id 记下来
export DIFY_APP_ID=<app_id>
node make-app-key.mjs            # 明文 app-xxx 只打印一次，不要提交进 git
```

## 7. 体验与取证

浏览器里在应用「调试与预览」直接对话（开关词要写在**句子最前面**，例如 `纯向量：…` / `全文：…` / `证据：…`）；命令行取证（可复现 `evidence/` 里的每个 JSON）：

```bash
export DIFY_APP_KEY=app-xxx
node run-app.mjs "帮我从数据库方向开始模拟一面，先问一道中级题" --out ../evidence/run-hybrid-demo.json
node run-app.mjs "证据：哪些写法会导致索引失效？" --out ../evidence/run-explain-evidence.json
node run-app.mjs "纯向量：TIME_WAIT 为什么要等 2MSL" --out ../evidence/run-mode-vector.json
node run-app.mjs "全文：连接池 maxLifetime 和哪个服务端参数有关系" --out ../evidence/run-mode-fts.json
node run-app.mjs "InnoDB 的 MVCC 是怎么保证一致性读的？" "我答：RR 下事务一开始生成 ReadView，之后每条 SELECT 都重新生成一个，所以能看到别的事务最新提交的修改。请打分并追问。" --turns 2 --out ../evidence/run-two-turns.json
node ablation.mjs                  # 1 遍预热 + 3 遍测量，重写 evidence/retrieval-ablation.md / .json
python3 routing-selftest.py --save # 从 DSL 抽「模式路由」源码跑话术回归 -> evidence/mode-routing-selftest.txt
```

`run-app.mjs` 走的是应用自己的 Service API（`/v1/chat-messages`，streaming），会把每个节点的 `status / elapsed_time / 输入输出 / LLM usage` 落到 JSON。它会额外打印一行自己从 SSE 里算出来的「检索小结：知识库命中 N 条（Top1 score）；工具命中 N 条（mode / took_ms / 是否含执行计划）」——**这行是脚本的独立核对，不要和应用回答里那行搞混**：回答末尾那行「检索小结｜seekdb 模式=…｜知识库节点命中=…块｜自研工具命中=…块｜工具端到端耗时=…ms」由 DSL 里的「检索小结」代码节点从 seekdb 返回值拼装、回答节点原样追加，两边数字应当一致（`run-*.json` 的 `summary` 字段就是脚本侧的那一份）。。

## 8. 常见报错对照表

| 现象 | 原因 | 处理 |
| ---- | ---- | ---- |
| 知识库文档索引失败 / worker 报 `hybrid search is disabled` | 建库时 `OCEANBASE_ENABLE_HYBRID_SEARCH` 不为 true | 改 `.env`/`seekdb.env` 后重建 seekdb 与 api，再 `import-kb.mjs --reindex` |
| 回答里「知识库节点命中=0 块」 | 知识检索节点 context 变量选择器写成 `results`（正确是 `result`），或知识库没切 hybrid_search | 检查 DSL `context.variable_selector`；跑 `set-dataset-hybrid.mjs` |
| 输入 `纯向量：…` 但小结那行仍是混合 | 开关词没写在句首，或弱关键词（`向量`/`全文`）后面没跟分隔符 | 句首写 `纯向量：` / `全文：`；边界可用 `python3 routing-selftest.py` 自证 |
| 回答里没有「检索小结｜…」那行 | 「检索小结（确定性）」节点没在链路上，或回答节点缺 `{{#1000000000007.summary#}}` | 确认 `edge-kr-summary` / `edge-tool-summary` / `edge-summary-llm` 三条边与回答模板 |
| 工具节点 `invalid input syntax for type uuid: "seekdb_hybrid_search"` | DSL 的 `provider_id` 不是本机工具 UUID | 用 `import-dsl.mjs` 导入（会自动改写），或在节点里重选工具 |
| 工具节点连不上 / squid `ERR_ACCESS_DENIED` | SSRF 代理拒绝私网 | 配 `SSRF_PROXY_ALLOW_PRIVATE_IPS` 并 `docker compose up -d ssrf_proxy` |
| 自定义工具注册报 `invalid mode value '0'` | 凭据结构不对 | 用 `credentials: {auth_type: "none"}`（脚本已处理） |
| `GET /apps/<id>/export` 500 `WorkflowNotFoundError` | 应用还没有草稿/已发布工作流 | 先 `--publish` 成功再 `--export` |
| EXPLAIN 结果是一堆空对象 | OceanBase 的执行计划是单个 `Query Plan` 文本列 | 已按文本列解析（`retrieval/server.mjs` 的 `explain()`） |
| Marketplace 装插件超时 | 容器内访问 `marketplace.dify.ai` 失败 | 用 `plugins/dist/*.difypkg` + `install-plugins.mjs`，并设 `FORCE_VERIFYING_SIGNATURE=false` |
| 模型回答里出现大段思考过程 | LLM 节点 `reasoning_format` 为默认 `tagged` | 设为 `separated`（DSL 已设），思考内容落到 `reasoning_content` 不进正文 |
| Git Bash 里 curl 发中文请求 400 | MSYS 把命令行参数转成了 GBK 字节 | 改用 Node 脚本发请求（本项目脚本均为 Node） |

## 9. 收尾：释放本机资源

```bash
bash dify/deploy/start-all.sh stop
cd dify/docker && docker compose down          # 数据卷在 ./volumes 下，知识库数据可保留
docker compose down -v                         # 需要彻底清空时（会删 seekdb 与 Postgres 数据）
```
