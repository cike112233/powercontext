# 知识库构建说明

本项目的知识库不是"把文档扔进去"，而是按**检索块 = 一道完整的可判分面试题**来设计的。这份说明讲清楚三件事：语料长什么样、为什么这样切、以及你想换成别的主题时怎么做。

## 2. 单条题目的固定模板

```markdown
### Q: <候选人会听到的原题，口语化，一句问完>
- 领域: 数据库
- 难度: 中级
- 考察点: <面试官真正想确认的能力>
- 参考答案要点: <3–6 条，分号连接，具体到机制/参数/数字>
- 追问: <2–3 个连环追问>
- 评分标尺: 及格=…；良好=…；优秀=…
- 常见误区: <1–3 条典型错误说法>
```

这么写的直接后果是：**检索命中一个块，LLM 就同时拿到了题目、答案要点、追问和评分标尺**，因此应用能做到"出题 → 判分 → 追问"闭环而不需要额外的数据表。这也是为什么参考答案必须写到机制与数字层面（例如"RR 下事务首次快照读生成 ReadView 并复用""`maxLifetime` 必须小于 `wait_timeout`，默认 30 分钟 vs 28800 秒"）——只有素材本身够具体，判分才可以说得出口，才不会出现"看起来像 AI 泛泛而谈"的观感。

内容底线（摘自 `CORPUS-SPEC.md`）：技术题必须写机制层面答案；至少 30% 的题带数字或参数；追问要能连成真实面试的一串对话；全部中文但保留英文术语原词；不写免责声明、不写文件末尾总结。

## 3. 分块策略：一道题 = 一个检索块

`scripts/import-kb.mjs` 用的是自定义分块，而不是 Dify 默认的 Markdown 标题分段：

```js
process_rule: {
  mode: "custom",
  rules: {
    pre_processing_rules: [
      { id: "remove_extra_spaces", enabled: true },
      { id: "remove_urls_emails", enabled: false },
    ],
    segmentation: { separator: "###", max_tokens: 1600 },
  },
}
```

配套的两个约束：

1. **题内不空行**。小节内部只用列表换行，避免被切碎成"题干一块、评分标尺一块"——切碎之后检索回来的块只有半道题，无法支撑判分。
2. **导入前剥掉文件前言**。`import-kb.mjs` 会把第一个 `###` 之前的内容（`# 文件标题` / `## 小节标题`）切掉：

   ```js
   const firstQ = raw.indexOf("### ");
   const text = firstQ > 0 ? raw.slice(firstQ) : raw;
   ```

   原因很实际：按 `###` 切分时第 0 片就是这段前言，它只有几十个字，却在全文通道里因为"数据库 / 面试"这类高频词稳定拿高分、把 Top1 抢走。剥掉之后 Top1 才干净。这一条是踩过之后才写进脚本的，`evidence/retrieval-ablation.md` 的结果是在剥皮之后的语料上跑出来的。

`max_tokens=1600` 是为了容纳"题干 + 考察点 + 参考答案要点 + 追问 + 评分标尺 + 常见误区"的完整一题（实测单块 636 字左右，见知识检索节点输出里的 `segment_word_count`）。

## 4. 混合检索开关：切完必须做，否则只有向量

Dify 的知识检索节点**自身没有 search_mode 字段**，用哪种检索方式取自**数据集自己的 `retrieval_model.search_method`**。默认值是 `semantic_search`，也就是只走向量——那样的话 seekdb 里即便建了 ik 全文索引也不会被用到。所以导入语料之后必须执行：

```bash
export DIFY_DATASET_ID=<import-kb.mjs 打印的 id>
node set-dataset-hybrid.mjs      # PATCH /datasets/<id> {retrieval_model:{search_method:"hybrid_search", top_k:5, reranking_enable:false, …}}
```

脚本会 PATCH 后再 GET 回读（回读字段是 `retrieval_model_dict`）并打印确认。这个操作**不需要重建索引**，改完立即生效；同时它也决定了 seekdb 建表时是否带 FULLTEXT 索引（`OCEANBASE_ENABLE_HYBRID_SEARCH=true` 且检索方式为 hybrid 时，Dify 才会走全文通道）。

顺带两个等价的手工路径，方便评委在界面上核对：知识库 → 设置 → 检索策略 选「混合检索」；或在知识库右上角「命中测试」里直接试问，看 Top1 是否是预期的那道题。

## 5. 导入与幂等

```bash
node import-kb.mjs              # 已存在同名文档则跳过，可重复执行
node import-kb.mjs --reindex    # 改了语料：先删同名文档再重建（会重写 seekdb 里的行）
```

脚本会轮询 `POST/GET /v1/datasets/<dataset_id>/documents/<batch>/indexing-status` 直到 `completed`，并打印每个文档的 `completed_segments` 与 `total_tokens`，最后列出知识库文档与段数。索引过程就是真实写 seekdb 的过程：worker 调本地 embedding（:8100）拿 512 维向量，再由 `OceanBaseVector` 插入 `vector_index_<dataset_id>_node`。核对：

```bash
curl -s http://127.0.0.1:3012/health        # "segments":162 —— 与题数一致，说明全部落库
docker exec seekdb sh -c "mysql -h127.0.0.1 -P2881 -uroot -pdifyai123456 -Dtest \
  -e 'SELECT COUNT(*) FROM vector_index_<dataset_id>_node'"
```

## 6. 换一个主题怎么做

整条链路对主题没有耦合，改三步即可：

1. 替换 `dify/kb/*.md`，遵守 §2 模板与 §3 两个约束（题内不空行、开头别写前言）。题目数不限，但建议 ≥100 才看得出混合检索与单通道的差异。
2. `node import-kb.mjs --reindex && node set-dataset-hybrid.mjs`。
3. 改 `dsl/interview-coach.yml` 里 LLM 节点的角色设定与 `features.opening_statement`/`suggested_questions`，然后 `node import-dsl.mjs ../dsl/interview-coach.yml --app-id <你的 app_id> --publish`。

`scripts/ablation.mjs` 里的 `QUERIES` 是按本题库标注的，换主题时同步替换 `expect` 子句即可复用消融实验。

## 7. 已知短板

- 512 维的 `bge-small-zh-v1.5` 语义分辨率有限，相近题目会互相抢位（消融里 hybrid 未进 Top1 的两条属此类）；换成更大的 embedding 模型只需改 `setup-models.mjs` 的模型名与 embedding 服务，检索链路不用动。
- 一题一块意味着"跨题综合"能力弱：问"把索引失效和 EXPLAIN 合起来讲"只会召回最相关的一题。真要综合，得靠多轮追问，而不是单次检索。
- 语料为参赛原创整理，覆盖后端校招/社招常见面点，不声称完备；超出题库的问题应用会明确回答"这块题库里没有，换个方向"。
