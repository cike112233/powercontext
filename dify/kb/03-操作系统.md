## 进程与线程

### Q: 进程、线程、协程差在哪，切换成本谁高？
- 领域: 操作系统
- 难度: 中级
- 考察点: 三者的资源边界与切换代价来源
- 参考答案要点: 进程是资源分配单位（独立页表加 fd 表），线程是调度单位、共享地址空间，协程是用户态任务、切换不陷入内核；线程切换约 1~5 微秒，只存寄存器与内核栈指针；进程切换还要换 CR3、刷 TLB 并污染 cache，贵几倍；协程切换只改栈指针，百纳秒级，Go 初始栈 2KB 可倍增；代价是失去隔离，野指针能拖垮整进程；内核 CFS 毫秒级抢占，协程默认协作式，Go 1.14 起才有基于信号的异步抢占
- 追问: 进程切换比线程切换贵在哪几步？；协程里跑纯计算死循环为什么会卡死事件循环？
- 评分标尺: 及格=分清资源单位与调度单位；良好=给出纳秒与微秒量级并提 TLB、cache；优秀=能讲 CR3、PCID 或异步抢占
- 常见误区: 认为线程切换不陷入内核；把协程当成内核调度实体

### Q: 上下文切换的开销具体花在哪，怎么发现切换过频？
- 领域: 操作系统
- 难度: 高级
- 考察点: 把切换开销拆成可观测成本项
- 参考答案要点: 直接成本是寄存器、内核栈与特权级切换，不到 1 微秒；更贵的是隐性成本：TLB miss、L1/L2 cache 冷启动、分支预测状态丢失、调度器红黑树 O(log N)；进程级切换端到端约 2~10 微秒；观测用 `vmstat 1` 的 cs 列、`pidstat -w`、`/proc/PID/status` 的 voluntary 与 nonvoluntary；自愿切换高暗示锁或 IO 等待，非自愿高说明线程太多被内核抢占
- 追问: 自愿与非自愿切换分别暗示什么？；cache 冷启动为什么比保存寄存器贵一个数量级？
- 评分标尺: 及格=列出寄存器、TLB、cache 三项；良好=给 vmstat、pidstat -w 与量级；优秀=解释两类切换含义并提跨核迁移代价
- 常见误区: 把切换只当成保存寄存器；只看 cs 总量不看类型比例

### Q: 进程间通信有哪些方式，各适合什么场景？
- 领域: 操作系统
- 难度: 中级
- 考察点: 每种 IPC 的内核路径与适用边界
- 参考答案要点: 管道半双工、限亲缘，缓冲默认 64KB，单次写不超 `PIPE_BUF`（4096 字节）才原子；命名管道按路径打开但仍单向；信号只传编号、不带数据、异步，适合通知；共享内存最快，内核只在建映射时介入、传输零拷贝，但需自配信号量或 eventfd 同步；消息队列保留边界但有内核拷贝；socket 可跨机，Unix domain socket 省协议栈且能用 `SCM_RIGHTS` 传 fd
- 追问: 共享内存为什么比管道快，省掉哪几次拷贝？；本机通信用 UDS 还是 TCP localhost，差别在哪？
- 评分标尺: 及格=报出五种以上方式并知信号不传数据；良好=给出 64KB、PIPE_BUF、UDS 传 fd；优秀=从拷贝次数与同步成本解释性能差
- 常见误区: 说共享内存不用系统调用；忽略管道写满会阻塞

## 内存管理

### Q: 虚拟地址怎么变成物理地址，页表和 TLB 各解决什么？
- 领域: 操作系统
- 难度: 中级
- 考察点: 多级页表与地址翻译的真实路径
- 参考答案要点: 每进程一套页表，按需分配物理页；x86-64 是 4 级页表，页 4KB、页表项 8 字节，一页装 512 项故每级取 9 位索引，地址拆成 12 位偏移加 4 段 9 位；一次翻译最坏 4 次访存，TLB 缓存结果，L1 约 64~128 项，未命中走页表遍历器；大页 2MB/1GB 缩短层级、显著减压 TLB，MySQL、Redis、DPDK 都开；PCID 给 TLB 打进程标签，切进程不必全刷
- 追问: 开大页为什么提速，少了多少次访存？；切进程必须刷 TLB 吗，PCID 解决什么？
- 评分标尺: 及格=讲清虚拟到物理加 TLB 是缓存；良好=给出 4 级、9 位、512 项的推导；优秀=能谈大页收益、PCID 与 shootdown
- 常见误区: 说进程独占物理内存；以为页表把地址空间建满；把 TLB 混同 CPU cache

### Q: 缺页中断是什么，页面置换为什么 Linux 不做真正的 LRU？
- 领域: 操作系统
- 难度: 高级
- 考察点: 按需分页、局部性与近似 LRU 的折中
- 参考答案要点: 缺页是 MMU 发现 PTE 无效或权限不符时陷入内核，分首次匿名页、映射文件页、被换出的页三类；SSD 换入约几十到上百微秒、HDD 毫秒级，纯内核态缺页约 1~2 微秒；置换靠局部性假设，FIFO 有 Belady 异常，严格 LRU 要给每次访问时间戳，硬件与内核都付不起；Linux 用访问位加 Clock 二次机会并分 active/inactive 链表，走一轮未被再命中才回收
- 追问: Clock 在什么访问模式下比 LRU 明显吃亏？；swap 缺页与 minor fault 成本差多少？
- 评分标尺: 及格=说缺页成因与淘汰动机；良好=讲清访问位、Clock 与双链表；优秀=能解释 LRU 开销代价与 `vm.swappiness` 默认 60
- 常见误区: 把缺页都当成读磁盘；说 Linux 用严格 LRU；认为访问位可精确排序

### Q: mmap 和 read/write 读文件的区别，什么时候用 mmap？
- 领域: 操作系统
- 难度: 中级
- 考察点: 两条 IO 路径的拷贝次数与故障模式
- 参考答案要点: read 两次拷贝：DMA 到 page cache 再 `copy_to_user`；mmap 只有一次 DMA，靠页表把 page cache 直接映射给用户，首次访问触发 minor fault；隐性成本是缺页次数与页大小成正比，1GB 文件按 4KB 页最多约 26 万次缺页，2MB 大页少 512 倍；风险是文件被 truncate 后访问收 SIGBUS、脏页异步回写需 `msync` 才落盘；小块随机读用 mmap，大块顺序流式用 pread 或 sendfile
- 追问: mmap 读大文件为什么可能比 read 慢？；自管 buffer pool 的系统为何偏用 pread？
- 评分标尺: 及格=答出少一次拷贝；良好=给出缺页与页大小关系并指出 SIGBUS；优秀=能对比 sendfile 零拷贝并给选型边界
- 常见误区: 说 mmap 零拷贝必然更快；混淆 minor 与 major fault

## 系统调用与进程控制

### Q: 系统调用怎么从用户态进内核态，为什么比普通函数贵？
- 领域: 操作系统
- 难度: 中级
- 考察点: 陷入机制与开销构成
- 参考答案要点: x86-64 用 `syscall` 指令（`int 0x80` 已淘汰）：CPU 从 MSR `IA32_LSTAR` 取内核入口、切内核段、把用户栈指针存入 per-CPU 变量、压寄存器造 pt_regs，再按 rax 调用号走 `sys_call_table`；参数走 rdi、rsi、rdx、r10，返回负值即 -errno；贵的不只是特权级切换，还有栈切换与 KPTI 带来的额外 CR3 切换；裸调用约百纳秒，落盘 write 或 futex 到微秒毫秒；优化靠 writev、vDSO、io_uring 摊薄
- 追问: KPTI 为什么显著加重系统调用成本？；io_uring 相比 epoll 加 read 省了哪几步？
- 评分标尺: 及格=答出陷入指令、调用号、栈切换；良好=区分 syscall 与 int 0x80 并给 vDSO；优秀=能连上 KPTI 与真实开销量级
- 常见误区: 说系统调用靠函数指针跳转；把 vDSO 当成绕过全部内核

### Q: fork、exec、wait 怎么配合，fork 到底拷了什么？
- 领域: 操作系统
- 难度: 中级
- 考察点: COW 语义与三件套分工
- 参考答案要点: fork 新建 task_struct、复制页表项并标只读加引用计数（写时才 COW 复制该页）、复制 fd 表与信号设置，父得子 PID、子得 0；耗时主要在页表拷贝，量级约每 1GB 已映射内存 1~3 毫秒，Redis bgsave 因此有内存翻倍风险；execve 把地址空间整个换掉重载 ELF，`posix_spawn`、vfork 就是跳过这步；`waitpid` 回收退出码；多线程进程 fork 只带调用线程，可能带着别人的锁进子进程，即 fork-safety
- 追问: 为什么说 fork 后立刻 exec 浪费九成工作？；子进程里能安全调用 malloc 吗，为什么？
- 评分标尺: 及格=说清复制、替换、回收分工；良好=给出页表拷贝量级与 fd 共享；优秀=能讲 fork-safety 与 posix_spawn 动机
- 常见误区: 以为 fork 拷贝全部物理内存；把 exec 说成创建新进程

### Q: 僵尸进程和孤儿进程分别怎么产生，怎么清理？
- 领域: 操作系统
- 难度: 初级
- 考察点: 进程终止与父进程回收的契约
- 参考答案要点: 僵尸（`ps` 显 Z）是子进程已退出但父没 wait，内核仍保留 task_struct、退出状态与 PID，会耗尽 `kernel.pid_max`（默认约 32768）；办法是父 wait，或装 SIGCHLD 后循环 `waitpid(-1,...,WNOHANG)`，因信号不排队、一次可能对应多个退出；孤儿是父先死子还在，交给 PID 1 或 `PR_SET_CHILD_SUBREAPER` 收养；容器坑在 PID 1 用 shell，不回收也不转发 SIGTERM，`docker stop` 只能靠 SIGKILL
- 追问: 信号不排队如何影响 SIGCHLD 的写法？；容器里 PID 1 该谁当，tini 解决什么？
- 评分标尺: 及格=区分没回收与没人管；良好=指出占 PID 与 pid_max；优秀=讲清信号不排队、subreaper 与 init 缺失
- 常见误区: 说僵尸吃大量内存；以为 kill 能杀掉僵尸

### Q: 信号是怎么送达的，为什么 SIGKILL 不能被捕获？
- 领域: 操作系统
- 难度: 中级
- 考察点: 信号投递的内核实现与陷阱
- 参考答案要点: 信号是异步通知，1~64 号，34~64 为实时信号可排队带 siginfo；发送只置 pending 位图并唤醒目标，真正处理发生在返回用户态前的 `get_signal`，所以在内核睡眠的进程不会立刻响应；SIGKILL(9)、SIGSTOP(19) 硬编码不可捕获，保证系统总能终止进程；坑是 SIGCHLD 不排队会丢事件、handler 里调 malloc 等非 async-signal-safe 函数可能死锁、写已关闭的管道得 SIGPIPE(13)，socket 要传 `MSG_NOSIGNAL`
- 追问: 进程卡在 D 状态时为什么 kill -9 也不生效？；三个子进程同时退出，一个 SIGCHLD 够吗？
- 评分标尺: 及格=知信号异步且 9、19 不可捕获；良好=说清返回用户态才处理并解释 D 状态；优秀=能讲不排队与 SIGPIPE
- 常见误区: 认为信号到就立刻打断执行；说 kill -9 永远有效

## IO 与并发

### Q: 五种 IO 模型怎么区分，阻塞和非阻塞阻塞了什么？
- 领域: 操作系统
- 难度: 中级
- 考察点: 按等待数据与拷贝数据两阶段拆解
- 参考答案要点: 一次 read 分两阶段：等数据到协议栈、从内核缓冲拷到用户缓冲；阻塞 IO 在第一阶段睡眠，可被信号打断返 EINTR；非阻塞立即返 EAGAIN 靠轮询；多路复用一个线程等多个 fd 的第一阶段，之后仍要 read 做第二阶段，本质同步；信号驱动 IO（SIGIO 加 `O_ASYNC`）靠通知但仍要自己读；异步 IO（POSIX AIO、io_uring）两阶段全由内核做完才是真异步；阻塞性是 fd 属性（`O_NONBLOCK`），同 fd 被两线程用会互相影响
- 追问: 为什么说 epoll 仍是同步 IO？；一个 fd 设了非阻塞会影响另一个线程吗？
- 评分标尺: 及格=说出五模型与两阶段；良好=明确多路复用只解决第一阶段；优秀=对比 io_uring 并指出 fd 属性的线程干扰
- 常见误区: 把多路复用当异步 IO；以为非阻塞本身提吞吐

### Q: select、poll、epoll 的区别，LT 和 ET 怎么选？
- 领域: 操作系统
- 难度: 高级
- 考察点: epoll 结构与边缘触发的编程义务
- 参考答案要点: select 用位图，上限 `FD_SETSIZE` 常为 1024，全量拷贝加双向 O(N) 且集合被改写要重置；poll 换成 pollfd 去掉 1024 但仍是全量拷贝加 O(N)；epoll 用红黑树存关注 fd、回调挂就绪链表、`epoll_wait` 只拷就绪事件，复杂度降为就绪数量级，`maxevents` 由调用方传（框架常用 1024），活跃 fd 少时优势极大；LT 默认、有数据就一直通知；ET 只在状态变化时通知一次，必须循环读到 EAGAIN，否则永久挂住
- 追问: ET 下为什么必须读到 EAGAIN？；多 worker 共用一个 epoll fd 会出什么问题？
- 评分标尺: 及格=答出 1024 与红黑树加就绪链表；良好=讲清 LT/ET 语义与 ET 义务；优秀=能指出 epoll 边界、惊群与 `EPOLLONESHOT`
- 常见误区: 说 epoll 是异步 IO；认为 ET 必然比 LT 更快

### Q: 死锁的四个必要条件是什么，工程上破坏哪条？
- 领域: 操作系统
- 难度: 中级
- 考察点: 从条件推出可落地的预防与检测
- 参考答案要点: 互斥、持有并等待、不可剥夺、循环等待，四条同时成立才死锁；破坏持有并等待=一次申请全部资源，利用率低；破坏不可剥夺=超时或抢占，如 `trylock` 后回滚重试；破坏循环等待=全局固定顺序加锁（按对象 ID 升序），最常用；互斥一般不可破；银行家算法要预知最大需求，实践少用；检测靠等待图找环，MySQL `innodb_deadlock_detect=ON` 回滚代价小事务、`innodb_lock_wait_timeout` 默认 50 秒
- 追问: 破坏不可剥夺与超时回滚在真实系统里长什么样？；两个事务反序更新同一批行怎么防死锁？
- 评分标尺: 及格=四条完整；良好=每条给出破坏手段与代价；优秀=用固定顺序、wait-for graph 与 `deadlock_timeout` 比较成本
- 常见误区: 说顺序反了就必然死锁；把活锁饥饿当死锁

## 排障、调度与容器

### Q: 内存一直涨怎么区分泄漏与正常占用，OOM 怎么查？
- 领域: 操作系统
- 难度: 高级
- 考察点: 有没有可复现的排查路径
- 参考答案要点: 分三类：泄漏是回收后对象不回落；碎片是 RSS 涨而应用已分配不涨；高水位驻留是 glibc free 后不还 OS（`M_TRIM_THRESHOLD` 默认 128KB）；看 smaps_rollup 的 Anonymous、`memory.events` 的 oom_kill；工具用 ASan、jemalloc heap profile；OOM killer 按 oom_score 挑进程（`oom_score_adj` 范围 -1000~1000），容器 OOMKilled 退出码 137
- 追问: 怎么证明是碎片而不是泄漏？；OOMKilled 和 OutOfMemoryError 有何不同？
- 评分标尺: 及格=区分三类并知 oom_score；良好=给 smaps_rollup、memory.events、137；优秀=讲清 malloc 阈值
- 常见误区: 只看 RSS 就断定泄漏；把 swap 用满等同内存泄漏

### Q: 递归把栈撑爆是怎么发生的，栈溢出和堆溢出有何不同？
- 领域: 操作系统
- 难度: 中级
- 考察点: 栈的布局与两类越界的行为差异
- 参考答案要点: 主线程栈大小由 `ulimit -s` 决定（Linux 默认 8MB），Go 协程从 2KB 起倍增；每帧含返回地址与局部变量，几十到几百字节，8MB 栈按每帧 100 字节约撑 8 万层；越界落到未映射的守护页触发写保护缺页，内核见超出 `RLIMIT_STACK` 即发 SIGSEGV；JVM 是 `-Xss`（默认约 1MB）超限抛可 catch 的 StackOverflowError；差别是栈越界立刻崩，堆越界只坏相邻对象、可能很久才炸
- 追问: Go 为什么能用 2KB 栈跑深递归而 C 不行？；StackOverflowError 被 catch 后栈为何又可用？
- 评分标尺: 及格=说清栈上限与两种表现；良好=给出 8MB、ulimit -s、-Xss；优秀=能解释守护页与 canary、sigaltstack
- 常见误区: 说超过 1000 层必爆栈；认为 StackOverflowError 不可恢复

### Q: top 里的 load average 怎么读，和 CPU 使用率什么关系？
- 领域: 操作系统
- 难度: 中级
- 考察点: load 的真实定义与跨系统差异
- 参考答案要点: 它是 R（运行或可运行）加 D（不可中断睡眠，多在等 IO）任务数的指数加权移动平均，取 1、5、15 分钟三窗口，衰减常数 60、300、900 秒；不是百分比，要跟核数比，`load/nproc` 小于 0.7 有余量、接近 1 开始排队、2~3 以上明显过载；陷阱是大量 D 状态（NFS 卡、磁盘慢）会推高 load 而 CPU 很低；BSD 与 macOS 只统计 R，不可跨系统比；定位用 `vmstat` 的 r 与 b 列分离 CPU 排队与 IO 阻塞
- 追问: load 高但 CPU 低最可能是什么，怎么证明？；D 状态进程为什么 kill -9 也无效？
- 评分标尺: 及格=知三窗口并与核数比；良好=答出 R 加 D 定义并解释高 load 低 CPU；优秀=用 vmstat r/b 区分瓶颈并指出跨系统差异
- 常见误区: 把 load 当 CPU 百分比；认为超过 1 就一定有问题

### Q: 硬中断和软中断怎么分工，网卡收包为什么要 NAPI？
- 领域: 操作系统
- 难度: 高级
- 考察点: 中断上下文的约束与延迟处理设计
- 参考答案要点: 硬中断在中断上下文运行，不能睡眠、必须极短，只确认设备与 ack；随后 raise 软中断，Linux 共 10 类含 NET_RX、BLOCK，在返回用户态或 idle 时由 `do_softirq` 批量处理；要睡眠就转 workqueue；NAPI 是因为每包一中断会造成中断风暴：收到中断后关该队列硬中断转轮询，一次 poll 预算 `NAPI_WEIGHT` 默认 64 包；观测 `/proc/softirqs` 看各核的 NET_RX；优化有 RSS 多队列、中断亲和 `smp_affinity`
- 追问: tasklet 和 workqueue 分别在什么时候用？；一个核 %soft 打满其余空闲你怀疑什么？
- 评分标尺: 及格=讲清硬中断短、软中断干活且不能睡；良好=列 NET_RX 并解释 NAPI 转轮询；优秀=给观测路径与 RSS、RPS 层次
- 常见误区: 说软中断就是内核线程；以为中断上下文可以加互斥锁

### Q: 容器靠什么隔离，为什么容器里 Java 读到的核数不对？
- 领域: 操作系统
- 难度: 高级
- 考察点: 隔离与限额分别由谁负责
- 参考答案要点: 隔离靠 namespace（PID、NET、MOUNT），限额靠 cgroup；CPU 限额 v1 看 `cpu.cfs_quota_us` 配 period 100000 微秒（quota 400000 即 4 核），v2 是 `cpu.max`；JVM 早期读 `/proc/cpuinfo` 拿宿主机核数，8 核 limit 在 64 核机上按 64 开 GC 线程被 CFS 节流；修复靠 8u191+ 的 `UseContainerSupport` 或 `-XX:ActiveProcessorCount`，看 `cpu.stat` 的 `nr_throttled`
- 追问: 只开 namespace 不开 cgroup 会怎样？；怎么确证线程被 CFS 节流？
- 评分标尺: 及格=答出隔离与限额分工；良好=说清 cpuinfo 来源与 UseContainerSupport；优秀=会用 cpu.stat 验证
- 常见误区: 把容器当有独立内核；以为改 nproc 能修 JVM
