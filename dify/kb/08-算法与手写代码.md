## 查找与选择类

### Q: 求数组里第 K 大的数，你会怎么写，两种做法复杂度差多少？
- 领域: 算法
- 难度: 初级
- 考察点: 能否给出两种以上解法并准确说清期望与最坏复杂度
- 参考答案要点: 最小堆维护 K 个候选：遍历 n 个元素，比堆顶大才 poll 再 offer，时间 O(n log k)、空间 O(k)，适合数据流与 k 远小于 n；快速选择：借用快排 partition，随机或三数取中选 pivot，把大于/小于 pivot 的分成两段，只在包含第 K 大的那一侧递归，规模近似 n+n/2+n/4…≈2n 故期望 O(n)，原地分区空间 O(1)，但最坏 O(n²)（pivot 连续取到极值）；直接排序是 O(n log n) 可过但非最优；第 K 大对应升序下标 n-k，边界极易写错；Java 用 PriorityQueue，Go 用 container/heap
- 追问: 100 亿个数在磁盘、内存只有 512MB 怎么求第 K 大？k 到 10^7 时快选还合适吗？多机分片的结果怎么合并才是精确的？
- 评分标尺: 及格=写出堆或快选任一种且复杂度对；良好=两种都讲清并指出快选最坏情况与随机化；优秀=能推导期望线性并给出分块+大顶堆/多路归并的外部方案
- 常见误区: 说快速选择是 O(n log n)；堆方案记成 O(n log n)；把第 K 大与第 K 个不同值混为一谈

### Q: 手写一个 LRU 缓存，get 和 put 都要 O(1)，你怎么实现？
- 领域: 算法
- 难度: 中级
- 考察点: 数据结构组合与指针操作的准确性，能否处理淘汰时的双结构同步
- 参考答案要点: HashMap<key, Node> 做定位 + 双向链表做访问顺序，用 dummy head/tail 哨兵省掉大量判空；get：map 取节点，命中就摘除该节点（node.prev.next = node.next; node.next.prev = node.prev）再插到 head 后，未命中返回 -1；put：key 存在则更新 value 并移到头部，不存在则新建节点头插并 map.put，size 超 capacity 时删 tail 前的最后一个节点且必须同步 map.remove(被淘汰的 key)；所有操作 O(1) 时间、O(capacity) 空间；Java 可直接用 LinkedHashMap(accessOrder=true) 覆写 removeEldestEntry；并发要加锁或按 key 分段；LFU 想保持 O(1) 需要频次桶 + 每频次的双向链表；Redis 是近似 LRU，每 key 记录最后访问时间的 1/3 粒度并按 maxmemory-samples（默认 5）采样比较
- 追问: 多线程下 get 也要移动节点，怎么保证原子又不太粗？容量按字节而不是条数怎么淘汰？LRU 在什么负载下反而不如 FIFO？
- 评分标尺: 及格=说出哈希+双向链表与命中移头部；良好=写对摘除/头插/淘汰尾部与 map 同步；优秀=能谈分段锁、LFU/ARC 与近似 LRU 的工程折中
- 常见误区: 用单向链表找不到前驱；只删链表忘删 map 造成泄漏；认为 get 是只读不用移动位置

### Q: 手写二分查找，你写过死循环吗，边界怎么定才不会错？
- 领域: 算法
- 难度: 中级
- 考察点: 是否用循环不变量推导边界，而不是靠试出来
- 参考答案要点: 二选一贯彻到底：`while (left < right)` 配 right = mid、left = mid + 1，区间 [left, right) 半开，退出时 left 就是 lower_bound（第一个 ≥ target 的下标）；`while (left <= right)` 配 left = mid + 1、right = mid - 1，闭区间 [left, right]，退出后 left 是插入点；死循环的唯一根源是区间没缩小——`left = mid` 又对 mid 下取整时会原地打转，修法是把 mid 改成上取整 `left + (right - left + 1) / 2`；防溢出写 `left + (right - left) / 2` 而不是 `(left + right) / 2`；旋转数组先判断哪半边有序再决定收缩方向；二分答案是把最优化转成单调 predicate 的判定问题
- 追问: 找第一个和最后一个等于 target 的位置你怎么写？为什么建议统一封装 lower_bound？有序数组二分和跳表查表该怎么选？
- 评分标尺: 及格=能写出无死循环的一个版本；良好=讲清不变量、两种取整规则与溢出写法；优秀=能用 lower_bound 复用解上界、旋转数组与二分答案
- 常见误区: 混用闭区间与 right = mid；(left+right)/2 在大下标下溢出；靠不断加 if 补丁试出边界而说不清理由

### Q: 求前 K 个高频元素，出现并列时你怎么处理？
- 领域: 算法
- 难度: 中级
- 考察点: 先聚合再选择的建模习惯，以及对并列语义的敏感度
- 参考答案要点: 第一步 HashMap 统计频次 O(n)；第二步对 (value, count) 取 Top-K：小顶堆维护 K 个，count 更大使整体大于堆顶时替换，O(n log k) 空间 O(k)；或快选按 count 找出第 K 大阈值 t 再收集所有 count ≥ t 的项；并列必须问清题面：第 K 名与第 K+1 名同频次时，"返回任意 K 个"要再加 tie-break（例如按 value），"全部返回"则结果可能多于 K；SQL 语义对应 row_number 硬截断、rank 跳号并保留并列、dense_rank 不跳号，深分页 limit offset 要换成游标式 where count < last；键基数极大且允许近似时先 Count-Min Sketch 估频次再进堆（误差 εN、置信 1-δ）
- 追问: 10 亿条日志的 URL 频次 Top-100、单机 8GB 怎么做？把每台机器的局部 Top-K 合并成全局 Top-K，为什么可能是错的？要求严格精确时你怎么保证？
- 评分标尺: 及格=给出哈希计数+堆两步；良好=能区分并列语义并解释 rank/dense_rank/row_number；优秀=能给出分片精确合并的论证或近似方案及误差界
- 常见误区: 不对频次排序却对原数组排序；声称局部 Top-K 合并必然精确；忘记 count 相同需要确定的 tie-break 导致测试随机失败

## 数组、字符串与链表

### Q: 最长不含重复字符的子串，用滑动窗口怎么写，left 为什么能直接跳？
- 领域: 算法
- 难度: 中级
- 考察点: 滑窗正确性论证，能否解释跳跃不破坏窗口不变量
- 参考答案要点: map 记每个字符最后一次出现的下标；right 逐个扩字符，若 last[c] ≥ left 说明 c 落在当前窗口内，把 left 直接跳到 last[c] + 1，再写 last[c] = right，每步用 right - left + 1 更新答案；left 可跳跃的依据是：新窗口内所有字符的最后出现位置都严格小于新 left，因此无重复，不需要逐位 left++ 重扫；时间 O(n)、空间 O(min(n, Σ))，纯 ASCII 用 int[128]、小写字母用 int[26]；判断必须写 last[c] ≥ left 而不是 > 0，否则 tmmzuxt 这类用例会把窗口退回到已经离开的重复字符；输出子串本身则额外记 start 与 maxLen
- 追问: 含中文或 emoji 怎么处理？允许最多一个重复字符时窗口怎么改？要求返回所有最长子串怎么办？
- 评分标尺: 及格=写出 set + 逐步 left++ 的版本；良好=讲清跳跃依据与 last[c] ≥ left 的坑；优秀=能处理 Unicode/多解输出并推广到最多 K 个不同字符
- 常见误区: 忘了和 left 比较导致窗口含重复；把子串写成子序列；用 while 收缩却仍声称 O(n) 常数小

### Q: 接雨水这题你会几种解法，双指针为什么不会漏算？
- 领域: 算法
- 难度: 高级
- 考察点: 多解法复杂度对比与双指针正确性的证明能力
- 参考答案要点: ①前后缀最大值 DP：预处理 leftMax[i] 与 rightMax[i]，累加 min(leftMax[i], rightMax[i]) - height[i]，O(n) 时间、O(n) 空间；②双指针：left/right 从两端向内，维护两侧历史最大值 leftMax/rightMax，谁的小就移动谁并结算该列，正确性在于移动侧的水位由较小的那侧决定，另一侧必然存在不低于它的屏障，故 min 值已确定，O(n) 时间、O(1) 空间；③单调栈（按横向层累加）：栈存高度递减的下标，遇到更高柱时弹出 mid，宽 = i - stack.peek() - 1，高 = min(height[i], height[stack.peek()]) - height[mid]，累加 width × height，O(n) 时间、O(n) 空间，注意它算的是逐层而不是每列；累加和要用 long 防溢出
- 追问: 为什么"谁小移谁"而不是比较当前高度？柱子宽度不等怎么改？三维接雨水你怎么建模？
- 评分标尺: 及格=给出暴力 O(n²) 或 DP 任一；良好=写清三种并指出 DP 与单调栈的几何意义差异；优秀=能证明双指针不变量并处理溢出与变形
- 常见误区: 双指针里维护的是当前高度而非历史最大值；单调栈的宽度少减 1；把逐列与逐层两种视角混着用

### Q: 反转链表你写一下，怎么判断有环并找出环的入口？
- 领域: 算法
- 难度: 中级
- 考察点: 指针操作的严谨性与 Floyd 判环的数学推导
- 参考答案要点: 迭代三指针：next = curr.next; curr.next = prev; prev = curr; curr = next，返回 prev，O(n) 时间、O(1) 空间；递归版回溯时做 head.next.next = head，且必须 head.next = null 断链否则成环，额外 O(n) 栈深；区间反转 [m,n] 用 dummy 加头插法；Floyd 判环：慢走 1 步快走 2 步，有环必相遇（追及距离是环长的整数倍），空间 O(1) 优于 HashSet 的 O(n)；找入口：相遇后一个指针回 head，两者同速每次一步，再次相遇即入口，设 head 到入口 a、入口到相遇点 b、环长 c，由 2(a+b) = a+b+n(b+c) 得 a 与 c 相差环长的整数倍
- 追问: 怎么判断两条单向链表相交，为什么比较尾节点就够了？反转后调用方怎么拿到新 head？
- 评分标尺: 及格=写出迭代反转与相遇判环；良好=能推导入口等距关系并处理断链；优秀=给出相交/环长/k 组反转推广与空间取舍
- 常见误区: 递归反转忘断 next 导致死循环；快指针初始位置与循环条件不匹配；坚信快慢指针可能在环上跳过而永不相交

## 树、图与动态规划

### Q: 二叉树层序遍历怎么写，最近公共祖先又有哪几种做法？
- 领域: 算法
- 难度: 中级
- 考察点: BFS 分层技巧与 LCA 递归语义的边界条件
- 参考答案要点: 层序用队列，每轮先取 size = queue.size() 作为本层个数即可分层输出；右视图取每层最后一个、锯齿形对层结果 reverse 或用双端队列、最小深度可在遇到叶子时 return 层号；时间 O(n)、空间 O(最大层宽)，完全二叉树最后一层约 n/2；LCA 递归后序：节点为空或等于 p/q 直接返回，左右递归结果都非空说明当前节点是分叉点即答案，否则返回非空一侧，O(n) 时间、O(h) 栈；BST 按大小关系迭代下探，平均 O(h)，退化成链状则 O(n)；带父指针时转成相交链表；静态多次查询用 parent 数组 + 倍增（O(n log n) 预处理、O(log n) 查询）或 Tarjan 离线
- 追问: 一百万节点且退化成链时递归版本会怎样，怎么改？如果 p 或 q 可能不在树里，你的返回语义要不要改？两个节点在同一条祖先链上答案是什么？
- 评分标尺: 及格=写出分层 BFS 与递归 LCA；良好=讲清 BST 迭代版与左右皆非空的语义前提；优秀=能给倍增/Tarjan 与节点缺失时的显式校验
- 常见误区: BFS 不分层直接打印；漏掉 p 是 q 祖先的情形；以为未校验存在性的 LCA 在节点缺失时仍然正确

### Q: 你怎么判断一个问题该用动态规划，01 背包和最长递增子序列分别怎么建状态？
- 领域: 算法
- 难度: 中级
- 考察点: 建模三要素是否成体系，以及遍历顺序背后的原因
- 参考答案要点: 两条判据：最优子结构（大问题最优由子问题最优拼成）与重叠子问题（朴素递归大量重复，可记忆化或改递推）；建模三要素：状态定义、转移方程、边界与遍历顺序，被依赖状态须已算出；01 背包：dp[j] = max(dp[j], dp[j-w[i]] + v[i])，物品在外层、容量逆序遍历以保证每件只用一次（正序即完全背包），一维滚动把 O(nm) 降到 O(m)，还原方案需保留选择表；LIS：dp[i] 定义为以 i 结尾的最长长度，枚举 j<i 得 O(n²)；更优是 tails 数组 + 二分 O(n log n)，但 tails 不是真实方案，还原要记 parent；规模 10^5 而方程 O(n²) 时要上单调队列优化
- 追问: 怎么从暴力递归系统地导出 dp 方程？要求输出具体 LIS 序列你怎么改？
- 评分标尺: 及格=说出两条判据并写对背包方程；良好=能解释逆序原因与一维压缩条件；优秀=能推广完全/多重背包并给出 O(n log n) LIS 与路径还原
- 常见误区: 01 背包容量正序遍历；把 dp[i] 定义成前 i 个的最长而非以 i 结尾；只写方程不说遍历顺序

### Q: 手写 KMP，next 数组到底是什么含义，为什么文本指针不用回退？
- 领域: 算法
- 难度: 高级
- 考察点: 失败函数的准确定义与复杂度推导，而非只会背代码
- 参考答案要点: next[i] 表示模式串前 i 个字符（p[0..i-1]）的最长相等真前缀与后缀长度；不同实现的索引约定差 1（有的以 -1 起始），写之前必须先声明约定；失配时文本指针 i 保持不动，只把模式指针 j 回退到 next[j]，因为回退后模式串已匹配部分的后缀与文本仍对齐，故总比较次数 O(n + m)，暴力是 O(n·m)；构建 next 时用同样的 j = next[j] 自相似回退，例如 "ababaca" 在 -1 约定下 next = [-1,0,0,1,2,3,0]；对比 Rabin-Karp 用滚动哈希适合多模式但要处理冲突再逐字符验证，Boyer-Moore 用坏字符+好后缀可大跳、平均亚线性，Z 函数可作 next 的等价替代
- 追问: 统计模式串在文本中出现多少次怎么改？多模式敏感词过滤你怎么做（AC 自动机）？
- 评分标尺: 及格=说出前后缀含义与不回退文本；良好=能手算 next 并给出 O(n+m) 论证；优秀=能讲清索引约定差异与 RK/BM/AC 的适用场景
- 常见误区: 把 next 说成最长公共子串；两种索引约定混用导致死循环；认为 KMP 在短模式上一定比 indexOf 快

### Q: 跳表为什么能替代平衡树，Redis 的 zset 为什么选它？
- 领域: 算法
- 难度: 高级
- 考察点: 概率结构的期望复杂度与工程可维护性的权衡
- 参考答案要点: 多层有序链表，插入时按概率 p 随机决定层数（Redis 用 p = 1/4、上限 32 层），查找从最高层向右直到本层太大再下降，期望比较与访问节点数 O(log n)，平均额外指针约 1/(1-p) 倍；相比红黑树/AVL 没有旋转，插入删除只改局部几个指针，实现简单不易出错；范围查询天然（定位下界后沿最底层向右扫，ZRANGEBYSCORE、ZRANK 都直接支持）；并发友好，只需锁被改动的少量节点或做 CAS 无锁化，而旋转会导致连锁结构调整，LevelDB/RocksDB 的 memtable、Lucene 都用它；代价是每节点多个指针、常数比树大；Redis 用跳表 + dict 双索引，member→score O(1)、按 score 定位 O(log n + m)，元素少（约 64 个以内）时切 listpack 省内存
- 追问: 跳表最坏会退化成什么样？Redis 为什么不选红黑树（提示：范围查询与序列化）？
- 评分标尺: 及格=说出期望 O(log n) 与实现简单；良好=给出 p、层高与范围查询/并发优势；优秀=能讲双索引、listpack 切换条件与 p 的影响
- 常见误区: 说跳表查找一定快于树；把它当有序数组二分；忽略它是概率结构、复杂度是期望而非保证

## 并发设计与复杂度权衡

### Q: 让你手写一个并发限流器，你怎么实现，速率和突发怎么区分？
- 领域: 算法
- 难度: 高级
- 考察点: 能否把限流语义落到可写的状态机并说清边界条件
- 参考答案要点: 令牌桶：状态只有 tokens、capacity、rate、lastRefill，不启后台线程，取令牌时按时间差惰性补充 tokens = min(capacity, tokens + (now - lastRefill) × rate)，够一个就扣减返回 true，O(1) 空间，允许 capacity 突发但长期受 rate 约束；漏桶固定速率出水、强制平滑且不允许突发；滑动窗口日志用 Deque 存时间戳，弹出过期后判断 size < limit；固定窗口计数器最简单，但切换瞬间可能放过 2 倍流量；Semaphore 限的是并发数不是速率，Guava RateLimiter 默认 SmoothBursty；Go 用 x/time/rate 的 Allow/Wait 或 channel 令牌桶 + ticker；时间源必须单调（System.nanoTime），否则 NTP 回拨会把桶灌满；被拒返回 429 + Retry-After；分布式用 Redis Lua 原子完成计算与扣减，或中心下发配额 lease 加本地兜底
- 追问: 50 台实例要限全局 5000 QPS 怎么做？按用户维度限流导致 key 基数爆炸怎么处理？
- 评分标尺: 及格=讲清令牌桶参数与惰性补充；良好=能区分限速率与限并发并指出单调时钟、分布式原子性；优秀=给出两级限流、时钟回拨、key 淘汰与拒绝策略的取舍
- 常见误区: 用 currentTimeMillis 做基准；把 Semaphore 当限速率；用 get+set 两步扣令牌导致并发超放

### Q: 内存装不下时算法上怎么做时间与空间的取舍，举个具体例子？
- 领域: 算法
- 难度: 高级
- 考察点: 能否用量级估算而非口号来论证取舍
- 参考答案要点: 10 亿个 32 位非负整数去重或判存在：位图 10^9 bit ≈ 119MB，单机可跑；值域到 64 位就改用哈希分桶或外部排序；布隆过滤器 1% 假阳约需 9.6 bit/元素、k ≈ 7 个哈希函数，10 亿元素约 1.2GB，有假阳无假阴、不支持删除（需 Counting Bloom 或 Cuckoo Filter）；只要计数时用 HyperLogLog，12KB 寄存器可估 10 亿基数、误差约 0.81%；外部排序：按可用内存 M 分块内排再多路归并，磁盘 IO 约 2N × 归并轮数，减少轮数靠加大归并度 k 与顺序 IO；DP 用滚动数组把 O(nm) 降到 O(m)，代价是丢掉回溯路径；索引与缓存是空间换时间，还要算写放大与一致性代价；结论要落到数字：数据量、单条大小、访问频次、可接受误差
- 追问: 只有 512MB 内存要求 10GB 文件的中位数怎么办？允许近似时你能承诺多大误差？
- 评分标尺: 及格=能举位图或外部排序一例并给量级；良好=会用 bit/元素与误差率算内存；优秀=同时给精确与近似两套方案并说明代价
- 常见误区: 因为布隆无假阴就当作可直接判定存在；10 亿 int 直接上 HashSet

### Q: 递归写法栈溢出了，怎么改成迭代，哪些递归能直接变成循环？
- 领域: 算法
- 难度: 中级
- 考察点: 对调用栈成本的认知与显式栈模拟的严谨性
- 参考答案要点: 尾递归（递归调用是最后一步且返回值不再参与运算，如带累加器的阶乘、快排单侧下探）可用 while + 变量更新直接替换，空间从 O(n) 降到 O(1)；非尾递归（树的遍历、带回溯的 DFS）必须用显式栈，栈帧里保存参数与阶段标志（enter/exit）才能复现前序/中序/后序，本质是把系统栈搬到堆，不受栈大小限制但仍耗内存；二叉树还有 Morris 线索化，O(1) 额外空间但临时改树须还原；量化：Java 默认 -Xss 1MB、单帧几十到几百字节，约 1 万层就 StackOverflowError，且 HotSpot 不做尾调用优化；Python 默认 sys.setrecursionlimit(1000)，调太大会撞 C 栈直接段错误；Go 栈可增长到 1GB 上限，但深递归仍耗内存并拖慢 GC 扫描
- 追问: 无向图 DFS 深度 10^6 你怎么改？怎么验证迭代版和递归版等价？
- 评分标尺: 及格=区分尾递归与非尾递归并写出显式栈；良好=给出各语言栈限制量级与 Morris 替代；优秀=讲清栈帧搬到堆的取舍与随机数据对拍验证
- 常见误区: 以为 Java/Python 会自动尾递归优化；把调大 recursionlimit 当解决方案；显式栈只压节点不压阶段，导致后序结果错误
