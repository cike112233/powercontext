# 给 stepfun 的任务：生成中文检索评测数据集

## 背景
我们在做一个「浏览器端向量化 + seekdb 混合检索」的迷你知识库应用（2026 OceanBase × 阶跃星辰 赛题）。
需要一份**中文评测数据集**来计算检索质量指标 Recall@K 和 NDCG@K。这是纯内容生成任务，不涉及代码运行。

## 交付物（一个 JSON 文件，UTF-8 编码）

```json
{
  "corpus": [
    { "id": "d01", "title": "...", "text": "..." },
    { "id": "d02", "title": "...", "text": "..." }
  ],
  "queries": [
    { "id": "q01", "text": "...", "relevant": ["d03", "d11"], "k": 5 }
  ]
}
```

## 硬性要求

1. **corpus：40 篇文档**
   - 每篇 `text` 长度 120–260 个汉字，是一个自包含的信息段落（不要列表、不要代码块）
   - 主题限定在以下技术域，均匀分布：分布式数据库、向量数据库、检索增强生成(RAG)、
     大模型端侧推理/量化、推荐系统、知识图谱、数据库索引与查询优化、AI Agent
   - 每篇要有区分度：**不要**出现两篇讲几乎同一件事；允许存在主题相邻但不等价的"干扰对"
     （例如两篇都提"向量索引"，一篇讲 HNSW 原理、一篇讲 IVF 量化），用来考验检索精度
   - `id` 用 d01..d40

2. **queries：20 条查询**
   - 每条是自然的中文问句或关键词短语，长度 6–25 字
   - `relevant` 是该查询在 corpus 中**所有**应被判为相关的文档 id（通常 1–3 篇，必须真实对应，不能乱标）
   - 查询类型要覆盖：① 关键词精确匹配型（考全文检索）② 语义改写型，措辞和文档不同但意思相同
     （考向量检索）③ 混合型 ④ 至少 2 条"陷阱查询"——字面像某篇但语义应命中另一篇
   - `id` 用 q01..q20

3. **质量红线**
   - 相关性标注必须可复核：每个 (query, relevant doc) 对，要能在文档里找到支撑依据
   - 语料和查询**全部简体中文**，不要混英文整句（专有名词如 HNSW/RAG 可以）
   - 不要生成真实公司名、人名、日期、URL

## 输出格式
只输出那个 JSON，不要额外解释。确保能被 `JSON.parse` 直接解析（无尾逗号、无注释）。
